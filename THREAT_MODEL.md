# Threat Model

A summary for security reviewers. It covers the five published packages: `@promql-validator/core`, `@promql-validator/react`, `promql-validator`, `@promql-validator/monaco` and `@promql-validator/codemirror`.

## What the packages handle

| Data | Source | What happens to it |
|---|---|---|
| Query text | The user typing, or the host app's `value` | Tokenized, parsed and validated in memory. Shown in the editor. Passed to host callbacks (`onChange`, `onValidation`, `suggestionProvider`). |
| Suggestions | Host app: static lists, dynamic groups, async provider results | Indexed and ranked in memory. Rendered as plain text. |
| Diagnostics | Generated by core, or by host-supplied validators and plugins | Rendered as plain text. Passed to `onValidation`. |
| Telemetry events | Generated by the React component, only if `telemetryHooks` is passed | Timings, counts, booleans and the host's `instanceId`. Never query text or suggestion values. |

Nothing is written to `localStorage`, `sessionStorage`, cookies or IndexedDB. The optional suggestion cache and "recently used" ranking live in memory and disappear on unmount or reload.

## Trust boundaries

- **The host app is trusted.** Validators, plugins and suggestion providers are code the host imports and runs; the packages never load code from anywhere.
- **Suggestion content is untrusted display data**, even when it comes from the host, because it often originates in user-controlled metric or label values.
- **Async provider output is untrusted structure.** It may be malformed, huge or arrive late.
- **Query text is untrusted input.** It may be arbitrarily long or deeply nested.

## Threats and mitigations

| Threat | Mitigation | Where |
|---|---|---|
| Script or markup injection via suggestion `label`, `detail` or `description` | Rendered as React text nodes; no `dangerouslySetInnerHTML` anywhere. Custom icons come from a host-provided `iconMap` keyed by string, not from suggestion markup. | `packages/react/src/SuggestionItemContent.tsx` |
| Malformed or oversized provider output | Validated per item at runtime: entries without string `label`/`value` are dropped; strings are capped (200 characters, 500 for descriptions); arrays are capped. | `sanitizeResults` in `packages/core/src/suggestions/async-controller.ts`, used by the React component and both adapters |
| Stale or out-of-order async responses | Each request gets an `AbortController`; a sequence number discards responses that arrive after a newer one. | `AsyncSuggestionController` |
| ReDoS / super-linear matching | The fuzzy matcher is a bounded, linear-time subsequence scan with no regular expressions. Prefix lookups use binary search over a sorted index. | `packages/core/src/suggestions/fuzzy.ts`, `indexing.ts` |
| Stack exhaustion from deep nesting | The parser stops at a nesting depth of 100 and reports `PQ_TOO_COMPLEX`. | `MAX_NESTING_DEPTH` in `packages/core/src/parser/parser.ts` |
| CPU exhaustion from huge input | Live validation is skipped above `maxQueryLength` (10,000 characters by default) with an informational `PQ_QUERY_TOO_LONG`. The parser reads at most 200,000 characters. | `packages/core/src/validator/validate.ts` |
| Crashes on arbitrary input | The lexer never throws (unknown characters become `Illegal` tokens), and a fuzz suite feeds hundreds of random inputs through the validator. | `packages/core/src/__tests__/fuzz.test.ts` |
| Data leaving the browser | No package calls `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource` or `sendBeacon`. A test scans every published source file and fails the build if one appears. Telemetry hooks are in-process callbacks with no string fields for query content. | `packages/core/src/__tests__/no-network.test.ts` |
| Supply-chain compromise | `@promql-validator/core` has no runtime dependencies. The other packages depend only on core and declare their framework as a peer. Releases are published from CI with npm provenance, and a CycloneDX SBOM is generated per package. | `.github/workflows/release.yml` |

## Out of scope

- What host-supplied validators, plugins and providers do (for example, network calls a provider makes).
- The security of the PromQL backend that eventually runs the query. Validation checks syntax and semantics; it isn't an authorization layer and doesn't make a query safe to run.
- Vulnerabilities in React, Monaco or CodeMirror themselves.

## Offline and air-gapped use

Parsing, validation, formatting and the built-in suggestion dictionaries need no network access, configuration or environment variables. The only network path is a `suggestionProvider` that the host writes.
